# AGENTS.md

Правила для ИИ-агентов и людей, работающих в этом репозитории. Прочитай этот
файл и `doc/vacv-qsar.md` перед первой правкой. Если правило мешает задаче —
скажи об этом явно, не обходи его молча.

## 1. Что это за проект

Хакатон VACV: модель машинного обучения, которая по SMILES-записи молекулы
предсказывает индекс селективности против вируса оспы (штамм VACV).

- Индекс селективности: `SI = CC50 / IC50` — отношение полумаксимальной
  цитотоксической концентрации к полумаксимальной ингибирующей.
- Основная задача — регрессия `SI` по структуре молекулы.
- Данных мало, поэтому половина ценности решения — собранная из открытых
  источников база и честная валидация, а не только модель.
- Официальная постановка, условия допуска и полное описание проекта:
  `doc/vacv-qsar.md`.

Соревнование: <https://www.kaggle.com/t/9150c85d954848faa7d298978c7a3a33>

## 2. Что должно быть в репозитории

К защите принимается репозиторий, из которого можно воспроизвести результат.
Обязательные артефакты:

1. **Pipeline** — одна команда от исходных данных до `submission.csv`,
   пригодного для загрузки в Kaggle.
2. **Скрипт выгрузки данных** — тянет соединения и измерения из открытых баз
   (ChEMBL и другие), сохраняет `smiles`, `ic50`, `cc50`, `si`, `doi`/ссылку на
   публикацию и проходит валидацию.
3. **Собранная база** — итоговый CSV в формате из раздела 4, закоммиченный в
   репозиторий.
4. **Скрипт обучения и проверки модели** — обучение, метрики, сохранение
   модели и предсказания.
5. **Функция `predict(smiles)`** — предсказание для новой молекулы, с
   предупреждением, если молекула вне области применимости.

Результат на Kaggle должен воспроизводиться: тот же pipeline, тот же порядок
метрики. Если меняешь пайплайн — проверь, что он всё ещё проходит целиком.

## 3. Структура репозитория

```
AGENTS.md

  vacv-qsar.md          # постановка задачи и материалы

  processed/            # clean.csv, splits.csv — генерируются
  rf/                   # отобранная таблица 408 строк: основная для обучения
  dataset.csv           # итоговая база, собирается из data/rf/train.csv
src/
  fetch/                # транспорт: манифесты, пагинация, кеш, провенанс
  sources/              # адаптеры источников (base.py, chembl.py, generic_csv.py)
  normalize/            # общие правила: единицы, цензурирование, SMILES
  dataset.py            # сборка и валидация data/dataset.csv
  features.py           # отпечатки и дескрипторы
  split.py              # разбиения train/val/test
  train.py              # CatBoost (--model catboost)
  predict.py            # инференс CatBoost
  random_forest.py      # RandomForest (data/rf, признаки уже готовы)
  pipeline.py           # сквозной запуск
scripts/                # вспомогательные скрипты
notebooks/              # эксперименты, не источник истины
tests/                  # pytest

```

Правила:

- Вся логика, которую нужно воспроизвести, живёт в `src/`, а не в ноутбуках.
  Ноутбук — черновик; готовый код переносится в `src/` и покрывается тестом.
- `data/raw/` и `data/processed/` — производные; в git попадает только то, что
  нужно для воспроизведения (см. раздел 7).
- Пути и параметры — через конфиг/CLI-аргументы, не хардкодом.

## 4. Контракт данных

Основная обучающая таблица — `data/rf/train.csv` (408 отобранных строк,
целевая колонка `SI VACV`). `data/dataset.csv` собирается из неё через
`sources/selected.mapping.yaml`; данные организаторов
(`data/organizers/train.csv`) оставлены только для справки. Модель
выбирается через `MODEL`: `make train MODEL=catboost` (по умолчанию) или
`make train MODEL=randomforest`; так же для `make submit`.

Единицы: концентрации в **мкМ** (µM). Если источник даёт нМ или мг/л —
переводи в мкМ на этапе сборки базы, а не в модели.

Обязательные колонки итоговой базы (`data/dataset.csv`) совпадают с
`train.csv` организаторов плюс провенанс:

| колонка | смысл |
|---|---|
| `Title` | идентификатор соединения из источника |
| `CC50_uM` | полумаксимальная цитотоксическая концентрация, мкМ (может быть пустой) |
| `IC50_uM_VACV` | полумаксимальная ингибирующая концентрация, мкМ (может быть пустой) |
| `SI VACV` | индекс селективности, целевая переменная (`CC50 / IC50`, если задана явно — берётся она) |
| `SI_lower` | нижняя граница SI (для цензурированных значений) |
| `SI_upper` | верхняя граница SI (`inf`, если не ограничена) |
| `SMILES` | структура молекулы |
| `strain` | штамм/организм из источника |
| `Culture` | клеточная линия |
| `doi` | DOI или ссылка на публикацию (пусто, если нет) |
| `source` | база-источник (`organizers`, `chembl`, `lab_x`, …) |

> **Утечка целевой переменной.** Колонки `CC50_uM` и `IC50_uM_VACV` нельзя
> использовать для построения моделей и предсказания целевой переменной:
> `SI` вычисляется из них математически (`SI = CC50 / IC50`), поэтому они
> оставлены только для общего кругозора. Использовать их разрешено
> исключительно для расчёта таргета и метки — и никогда как признаки.
> То же относится к производным: `pIC50`, `pCC50`, их отношениям и любым
> комбинациям. В признаки идёт только структура молекулы (SMILES, отпечатки,
> дескрипторы), а не измерения активности или токсичности.

Накопительная таблица всех найденных источников — `data/found.csv`
(собирается командой `python -m src.registry`). В ней колонки
`data/dataset.csv` плюс `source` и `status` (`ready`, если SMILES есть,
иначе `needs_smiles`). Новые источники добавляются сюда, а в
`data/dataset.csv` попадают только строки со SMILES.

Правила:

- Цензурированные значения не выбрасываются: `>`/`>=` дают нижнюю границу,
  `<`/`<=` — верхнюю. SI хранится как интервал `[SI_lower, SI_upper]`;
  точечное значение `SI VACV` выставляется, когда пара точная или SI задан
  источником. Потолок организаторов сохраняется: при пустом IC50
  `SI VACV = 10000` означает `SI_lower = 10000, SI_upper = inf`.
- Внешний SI вычисляется из пары IC50 и CC50 на известной клеточной линии
  и, для ChEMBL, в рамках одной публикации; реплики усредняются медианой.
  Неинформативные интервалы (`[0, inf]`) и измерения без второй стороны
  уходят в `dropped.csv` на стадии `pair`.
- Дополнительное округление концентраций и SI при сборке базы не применяется.
- Каждая отброшенная строка попадает в `data/processed/dropped.csv` со стадией
  `parse` (единицы/значения), `pair` (нет пары) или `validate` (нарушен
  контракт). Молча ничего не выбрасывается.
- Порог бинарной метки — параметр конфига, по умолчанию `SI >= 10`. Не
  зашивать 10 в код в нескольких местах.
- Внешние данные добавлять только если организаторы разрешили; проверять
  пересечение с тестом и фиксировать источник для каждой строки.

## 5. Моделирование и валидация

- **Никогда не подавать в модель `CC50_uM`, `IC50_uM_VACV` и их производные**
  (`pIC50`, `pCC50`, отношения): это утечка таргета. Они допустимы только для
  расчёта `SI` и метки. Проверять это в тестах на список признаков.
- Целевая переменная по умолчанию — `log10(SI)`; метрики регрессии считать на
  этой шкале и дополнительно сообщать исходную.
- Основное разбиение — **scaffold split**. Случайное разбиение допустимо
  только как справочная точка рядом, не вместо него.
- Тест не трогать до финальной проверки. Всё, что подбирается (гиперпараметры,
  порог, признаки), — только на train/val или в кросс-валидации.
- `splits.csv` фиксируется один раз (seed + явные id) и дальше не меняется,
  чтобы метрики были сравнимы между участниками.
- Сиды фиксировать и указывать в конфиге. Результат должен повторяться.
- Порядок работы: сначала простой бейзлайн (Morgan + CatBoost/LightGBM), потом
  улучшения (Chemprop, ансамбль, Optuna). Не начинать со сложной модели.
- Для бинарной метки сообщать ROC-AUC и PR-AUC (при дисбалансе PR-AUC важнее),
  для регрессии — RMSE/MAE/R². Всегда указывать, на каком разбиении считано.
- Отдельно проверять область применимости: расстояние до ближайшей обучающей
  молекулы и поведение `predict` вне неё.

## 6. Воспроизводимость

- Python 3.11+. Зависимости — в `requirements.txt` с закреплёнными версиями.
- Из чистого клона должны работать:
  - `make data` — собрать базу (или проверить, что она уже в репозитории);
  - `make train` — обучить модель;
  - `make submission` — получить `submissions/submission.csv`.
- Сетевые операции — только в скриптах выгрузки. Обучение и инференс не должны
  ходить в сеть.
- Не коммитить виртуальные окружения, кэши, веса и `submission.csv` больше
  оговорённого размера.
- Если меняешь формат входа/выхода, конфиг или CLI — обнови `README.md`.

## 7. Правила репозитория и безопасность

Никогда не коммитить:

- токены, пароли, ключи, `.env`, содержимое `~/.ssh`;
- персональные данные и всё, что запрещено лицензией источника;
- большие бинарные файлы (модели, архивы, дампы) без явного решения команды.

Данные организаторов и лицензионно ограниченные выгрузки держать в
`data/raw/` под `.gitignore`; в git — только то, что разрешено публиковать.
Итоговую базу `data/dataset.csv` коммитить, если лицензии источников это
позволяют; если нет — приложить скрипт, который её воспроизводит.

`id` манифеста должен быть безопасным именем каталога: `.` и `..` запрещены.
Engine дополнительно проверяет, что запись и удаление файлов не выходят за
пределы `out_dir`.

### Доступ к GitHub по SSH

Репозиторий приватный: доступ выдаётся через GitHub → Settings → Collaborators,
приглашение нужно принять. Ключ `~/.ssh/id_ed25519` добавляется в свой аккаунт
GitHub, а не в репозиторий.

Если в сети закрыт 22-й порт (`Connection closed ... port 22`), использовать SSH
через 443, прописав в `~/.ssh/config`:

```
Host github.com
    HostName ssh.github.com
    Port 443
    User git
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

Проверка: `ssh -T git@github.com` должен ответить `Hi <ник>!`. Если и 443
закрыт — клонировать по HTTPS с personal access token.

## 8. Коммиты

Стиль — как в ядре Linux.

- Заголовок: повелительное наклонение (`add`, `fix`, `remove`, `rework`), без
  точки, до 72 символов, цель — около 50.
- Если правка затрагивает подсистему — префикс `subsystem: краткое описание`.
  Используемые подсистемы: `data`, `fetch`, `features`, `model`, `eval`,
  `pipeline`, `test`, `build`, `docs`, `repo`.
- Пустая строка между заголовком и телом обязательна.
- Тело объясняет **почему**, а не только **что**: какую проблему решает патч,
  почему выбран такой подход. Перенос строк ~72 символа.
- Один коммит — одна логическая правка. Не смешивать рефакторинг, новую
  функциональность и переформатирование.
- Формат сообщения:

```
subsystem: краткое описание

Что делает патч, какую проблему решает и почему выбран такой подход.
Перенос строк ~72 символа.
```

- Коммиты не подписываются: никаких `Signed-off-by`, `git commit -s` не
  использовать.
- Сообщения и документация — по-русски; идентификаторы, имена функций и
  ключевые технические термины — по-английски.
- Не делать `--amend` для уже отправленных коммитов, не делать force-push в
  общие ветки, не пропускать хуки.

## 9. Правила кода

- Python, PEP 8, понятные имена, type hints в публичных функциях.
- Комментарии — только там, где причина не очевидна из кода. Не пересказывать
  код комментарием.
- Мелкие модули с одной ответственностью; общую логику выносить, а не
  копировать между ролями и скриптами.
- Ошибки данных (невалидная SMILES, отсутствующая колонка, деление на ноль при
  расчёте SI) обрабатывать явно: пропуск с записью в журнал, а не `except: pass`.
- Любая новая функция пайплайна — с тестом в `tests/`. Минимум: smoke-тест на
  маленьком фикстурном CSV.
- Перед коммитом запускать `make lint` и `make test` (если цель ещё не создана —
  создать её вместе с первым кодом, а не обходить проверку).

## 10. Рабочий процесс агента

Перед началом:

1. Прочитать `AGENTS.md` и относящийся к задаче раздел `doc/vacv-qsar.md`.
2. Посмотреть `git status` и не трогать чужие незакоммиченные правки.
3. Проверить, что задача не меняет контракт данных незаметно для остальных.

После работы:

1. Прогнать доступные проверки (`make test`, `make lint`).
2. Убедиться, что `make submission` всё ещё проходит, если правка его касается.
3. Обновить документацию, если изменился интерфейс.
4. Коммитить только по явной просьбе пользователя.

Спросить перед тем, как: добавлять тяжёлую зависимость, менять контракт данных,
удалять или перегенерировать `data/dataset.csv`, менять `splits.csv`, вводить
новый формат submission.
